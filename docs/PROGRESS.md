## Decisions confirmed

- Store model: Single-Vendor.
- Primary database: PostgreSQL 18.
- Environments: local development and Docker Compose.
- API-first backend; frontend is a separate future client.
- Modular Monolith; not microservices.
- Initial market: Iran; default locale `fa-IR`; timezone `Asia/Tehran`; persist instants in UTC.
- Store price and commerce amount unit: whole-integer toman (`long` / PostgreSQL `BIGINT` / JSON integer).
- Identifier strategy: UUIDv7 generated by the application and stored as PostgreSQL `uuid`.
- Runtime/framework baseline: .NET 10 LTS, ASP.NET Core 10 and C# 14.
- ORM/provider baseline: EF Core 10.0.15 and Npgsql EF Core provider 10.0.3.
- Customer authentication: username/password or SMS OTP sent by text message to a previously verified mobile number; SMS channel confirmed by owner on 2026-11-14.
- Staff authentication: username/password plus mandatory TOTP MFA; SMS OTP is not accepted for staff MFA.
- Access and refresh tokens: separate HttpOnly cookies; refresh token values are stored only as cryptographic hashes; rotation and reuse detection required.
- OTP initial policy: 6 digits, 2-minute expiry, 60-second resend cooldown, 5 failed attempts per challenge, 5 sends/phone/hour and 10 sends/phone/24 hours; configurable.
- OTP challenge and shared per-phone/global SMS quotas are persisted and updated atomically in PostgreSQL. ASP.NET Core per-IP rate limiting and edge/WAF protection complement these controls.
- SMS provider is intentionally not selected yet; provider adapter remains independent.
- Refresh replay policy: strict; a valid consumed-token replay revokes the owning session, with no grace window.
- Account classification: explicit, server-controlled `Customer` or `Staff`, independent of roles.
- Initial authorization: server-issued JWT role claims mapped through ASP.NET Core policies; no per-request Identity lookup. The accepted stale-role/session-revocation window is the remaining access-token lifetime (target 5 minutes) plus configured clock skew.
- JWT signing: RSA/RS256, minimum 3072-bit key, unique `kid`, public-key overlap during rotation, and fail-closed production startup.
- Browser topology: `shop.com`, `panel.shop.com`, `api.shop.com`; host-only HttpOnly cookies, Secure in production, SameSite=Lax, exact credentialed CORS allow-list and independent CSRF + Origin checks.
- Staff MFA pre-authentication uses a dedicated five-minute `__Host-staff-mfa` cookie; it does not create a normal session.
- ASP.NET Core antiforgery cookie + JSON request token; frontend keeps request token in memory and sends `X-CSRF-TOKEN`.
- Session policy: Customer 30-day absolute / 7-day idle; Staff 12-hour absolute / 30-minute idle. Customer session listing/revocation UX is defined; IP is not shown.

## Phase 2 implementation progress

- Slice 2A complete and merged in PR #8: explicit `AccountType` (`Customer` / `Staff`) persisted independently of roles, with application validation and a PostgreSQL check constraint. Migration intentionally fails if existing users require classification; no implicit backfill is permitted.
- Slice 2B implementation on `phase-2/session-refresh-persistence`: added UUIDv7 `AuthSession` and `RefreshToken` persistence, database constraints for session lifetimes/hash length/token-chain state, a partial unique index enforcing at most one active refresh token per session, and a PostgreSQL transaction-based rotation service. Rotation locks the session before the token, verifies the secret in constant time before and after locking, uses database time, consumes the old token conditionally, and commits session activity plus exactly one successor atomically. A valid consumed-token replay revokes only its owning session and active token; a token-ID match with the wrong secret does not revoke anything.
- Added PostgreSQL integration coverage for successful rotation, wrong-secret non-revocation, strict replay revocation and concurrent same-token refresh attempts. No HTTP authentication endpoints, JWT issuance or cookie handling are included in this slice.

- Added the `Ecommerce.Modules.Identity` project and registered it in the API host.
