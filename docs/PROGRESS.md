## Decisions confirmed

- Store model: Single-Vendor.
- Primary database: PostgreSQL.
- Environments: local development and Docker Compose.
- API-first backend; frontend is a separate future client.
- Modular Monolith; not microservices.
- Authentication target: JWT access + refresh tokens in separate HttpOnly cookies with CSRF defenses.
- Initial target country/market: Iran.
- Store price and commerce amount unit: whole-integer toman amounts (`long` / PostgreSQL `BIGINT` / JSON integer).
- Identifier strategy: UUIDv7 generated by the application and stored as PostgreSQL `uuid`.
- Default store language/locale: Persian (`fa-IR`); store timezone: `Asia/Tehran`. Persist instants in UTC.
- Inventory reservation strategy: transactional `ReservedQuantity` counter maintained atomically with reservation records in PostgreSQL.
- Reservation TTL: 15-minute default, configurable for new reservations at store level; each reservation stores its absolute expiry.
- Backorders: configurable per product/variant, disabled by default (`NoBackorders`); supported modes are `NoBackorders`, `AllowBackorders` and `AllowBackordersNotify`; variant setting overrides product setting.
- Runtime/framework baseline: .NET 10 LTS, ASP.NET Core 10 and C# 14.
- ORM/provider baseline: EF Core 10.0.15 and Npgsql EF Core provider 10.0.3; versions are centrally pinned and stable.

## Current blockers / verification

- Npgsql EF Core provider 10.0.3 targets .NET 10 and depends on EF Core >= 10.0.4 and < 11.0.0 and Npgsql >= 10.0.3; selected versions are aligned.
- No business module currently owns persisted tables. Therefore no shared/empty DbContext or artificial migration has been added. The first module will introduce its own DbContext and migrations.
- This execution environment has no .NET SDK or Docker CLI, so local build/test/Compose execution cannot be claimed. CI is configured for a PostgreSQL-backed integration test run; its result must be observed before Phase 1 is considered verified.
